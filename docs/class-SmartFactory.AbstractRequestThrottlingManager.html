Class: AbstractRequestThrottlingManager

abstract
abstract class AbstractRequestThrottlingManager implements IRequestThrottlingManager { }

Implements request limits, history expiry and retry delays for interchangeable storage backends.

Details

Subclasses supply history reading, persistence and an atomic execution boundary. The boundary must protect the complete read/check/write operation for the same caller key across processes. Caller keys are hashed once and passed explicitly to each storage hook. Rejected requests are not recorded. Backends maintain expiry of inactive callers independently. The interface remains the dependency and factory contract for concrete implementations.

Method: AbstractRequestThrottlingManager::executeAtomically()

abstract protected function executeAtomically(string $key, callable $operation): int;

Executes one admission operation while protecting the caller's history against concurrent updates.

Details

Subclasses must invoke the callback exactly once after acquiring a lock or equivalent transaction for this key, commit successful updates and release resources in a finally block. Protection must include the first admission for a key with no stored history yet. Shared-file implementations may lock the entire file to preserve unrelated callers' records. Locking only loadRecords() and saveRecords() independently is insufficient: another caller could reserve the same remaining slot between those operations.

Parameters

Name Pass type Value type Default value Description
$key by value string

The lowercase SHA-256 caller hash used by every storage hook in this operation.
$operation by value callable(): int

The complete clock/read/check/write operation to execute inside the protected boundary.

Returns

int

Returns the callback's admission result unchanged.

Throws

\RuntimeException

If acquiring, committing or releasing the storage protection fails.

\Throwable

If the admission callback fails; its failure must propagate after resources are released.

Validates and applies rolling-window limits without changing shared request history.

Details

Subclasses should validate storage settings before calling this implementation and commit their validated settings afterward, preserving the old configuration on failure.

abstract protected function loadRecords(string $key): array;

Reads and validates one caller's retained history inside its atomic execution boundary.

Parameters

Name Pass type Value type Default value Description
$key by value string

The lowercase SHA-256 caller hash supplied to executeAtomically().

Returns

list<float>

Returns only this caller's timestamps, ordered from oldest to newest. Equal timestamps represent separate requests and must remain separate entries. Timestamps are finite, nonnegative Unix seconds with microsecond precision. Missing history returns an empty array; malformed or unavailable existing history must not be treated as empty.

Throws

\RuntimeException

If history cannot be read or does not satisfy the storage schema and timestamp ordering.

Method: AbstractRequestThrottlingManager::registerRequest()

public function registerRequest(string $key): int;

Atomically reserves one request if every rolling-window limit permits it.

Parameters

Name Pass type Value type Default value Description
$key by value string

A nonempty caller identity supplied by the request handler.

Returns

int

Returns zero when admitted, or the longest required delay rounded up to whole seconds, capped at PHP_INT_MAX. Rejected requests do not change stored history. Accepted requests remove this caller's history older than the longest configured period. Other callers' history and its background expiry remain the responsibility of the storage backend. Future timestamps are retained if the system clock moves backwards. Elapsed times use microsecond precision so fractional window boundaries expire exactly.

Throws

\InvalidArgumentException

If the caller key is empty.

\LogicException

If init() has not successfully initialized the manager.

\RuntimeException

If locking, the clock, reading, history validation or persistence fails. Storage failures deny admission; the backend must release any acquired lock.

\Throwable

If a storage hook or overridden clock propagates another exception or error through atomic execution.
