Interface: IRequestThrottlingManager

interface IRequestThrottlingManager extends IInitable { }

Atomically enforces every configured rolling-window limit for an opaque caller key.

Details

Storage implementations may use files, databases or Redis. Checking limits and recording an allowed request must be one atomic operation across all processes sharing the storage. A limit is [maximum request count, period in seconds]. All limits apply simultaneously to the interval (current time - period, current time]. Rejected requests are not recorded. Clock rollbacks may retain future records conservatively instead of resetting budgets. The abstract base class provides the shared algorithm for backends that only need to implement history reading, persistence and atomic execution.

Method: IRequestThrottlingManager::registerRequest()

public function registerRequest(string $key): int;

Atomically checks every window and records the request only when all windows allow it.

Parameters

Name Pass type Value type Default value Description
$key by value string

A nonempty opaque identity, such as a normalized IP address, user ID, API-key identifier or one shared key for a global budget. The same key shares limits across API actions.

Returns

int

Returns zero when admitted, or a positive Retry-After delay rounded up to whole seconds until every limit permits another request, assuming no other requests are admitted meanwhile. A rejection must not change request history.

Throws

\InvalidArgumentException

If the caller key is empty.

\LogicException

If the implementation requires initialization and has not been initialized.

\RuntimeException

If shared history cannot be read, locked, validated or updated; admission must not be granted.
