Class: ApplicationSettingsManager

class ApplicationSettingsManager extends AbstractDatabaseSettingsManager { }

Stores application-wide settings centrally in a database as a JSON document.

Details

Central storage allows an application distributed across several servers to share the same settings. A stable record key identifies the document. Saves lock that key, read the latest document and merge only explicitly edited parameters in one transaction. Concurrent edits to other parameters survive; the last save wins for the same parameter. Values are cached in this object; call loadSettings() to refresh a long-lived instance. Contextual validation supports separate forms, but drafts are not stored between requests.

Method: ApplicationSettingsManager::init()

public function init(array $parameters): void;

Configures database-backed settings without loading them immediately.

Parameters

Name Pass type Value type Default value Description
$parameters by value array{ dbworker: DBWorker, settings_table: string, settings_column: string, settings_id_column?: string, settings_id?: int, no_own_transaction?: bool }

The worker, table and JSON column. The unique, non-generated integer key defaults to id = 1. A missing document is created on the first save. When no_own_transaction is true the caller must already have started a READ COMMITTED transaction. The settings table must provide the configured unique document key.

Returns

void

Discards the previous snapshot and unsaved edits.

Throws

\InvalidArgumentException

If the worker, identifier names or document key have invalid types or values, or the key column and JSON column have the same name.
