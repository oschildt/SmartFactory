Class: DBRequestThrottlingManager

class DBRequestThrottlingManager extends AbstractRequestThrottlingManager { }

Persists one caller's request history in one database row under a transactional logical-key lock.

Details

Uses DBWorker::lock_record(), including keys without a stored row, and save_records() for bound upserts. The configured database needs the target table and DBWorker's dbworker_locks service table. Each admission owns a READ COMMITTED transaction so application rollbacks cannot refund requests. Connected clones preserve the caller's prepared statement while sharing its native connection.

Method: DBRequestThrottlingManager::executeAtomically()

protected function executeAtomically(string $key, callable $operation): int;

Serializes one caller's complete admission operation inside an owned READ COMMITTED transaction.

Parameters

Name Pass type Value type Default value Description
$key by value string

The lowercase SHA-256 caller hash supplied by the inherited admission algorithm.
$operation by value callable(): int

The complete clock/read/check/write operation to run after acquiring the caller's logical-key lock.

Returns

int

Returns the admission result only after committing and releasing the logical-key lock.

Throws

\LogicException

If no worker is configured, admission is nested, or the configured connection already has a managed transaction. Use a separate connection when application work is already transactional.

\InvalidArgumentException

If the worker's schema produces an unsupported qualified table name.

\Throwable

If connecting, cloning, starting, locking, the callback, committing or statement cleanup fails. DBWorkerException failures are wrapped in RuntimeException with the original cause so handlers report 500. Owned transactions are rolled back after failures when still active. A rollback or cleanup failure does not replace the original failure; a connection whose rollback failed needs caller recovery.
